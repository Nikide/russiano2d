# Тесты веб-сборки

Здесь живёт то, что проверяет **веб-сборку движка** (Emscripten + SDL_GPU с
WebGPU-бэкендом). Нативные тесты движка лежат в `tests/agent/` и `tests/*/`;
они остаются как есть, потому что проверяют логику и физику, а не кадр в
браузере.

## `smoke.py` — дымовой прогон страницы

```bash
python3 tests/web/smoke.py --build-dir /tmp/r2d-web/build --headed   # смотреть глазами
python3 tests/web/smoke.py --build-dir /tmp/r2d-web/build            # headless
python3 tests/web/smoke.py --build-dir /tmp/r2d-web/build \
    --engine-args="--game,demos,--scene,shooter_witch" --frames 600 --headed
```

> **Про headless честно.** Headless-режим на этом спайке не подтверждён: движок
> в нём стартует (в журнале видно `first-frame`, текстуры и RmlUi), но страница
> не доходит до остановки за отведённое время, и вердикт `R2D-WEB-SMOKE` не
> приходит. Рабочая проверка — `--headed`: движок видно глазами, а прогресс и
> вердикт приходят на сервер маячками (`/__r2d_progress`). Headless стоит
> доводить отдельно (виртуальное время против `requestAnimationFrame` и Asyncify).

Что делает:

1. поднимает локальный HTTP-сервер над каталогом веб-сборки
   (`russiano2d.html/.js/.wasm/.data` — их кладёт сборка, см.
   [docs/WEB_EXPORT.md](../../docs/WEB_EXPORT.md));
2. открывает страницу с `?args=--frames,150&autostart=1`, то есть движок
   обязан сам нажать «Играть» и остановиться после 150 кадров;
3. печатает DOM и ищет маркер `R2D-WEB-SMOKE: ok colors=N bright=M`.

Маркер `R2D-WEB-SMOKE` печатается страницей, но **вердикт ставится по журналу
движка**, а не по пикселям: `drawImage` по WebGPU-canvas в части состояний
отдаёт пустое изображение, поэтому «colors=1» ничего не говорит о рендере.
Достоверные признаки — маячки страницы (`/__r2d_progress`):

| Маячок | Что значит |
|---|---|
| `first-frame` | движок отрисовал первый кадр (по нему страница гасит экран загрузки) |
| `stopped: R2D-WEB-SMOKE: …` | движок остановился по `--frames`; в строке — справочная статистика кадра |
| `shutdown: gpu-idle → script-exit → audio → app → done` | шаги завершения: видно, на каком страница «залипает» |
| `abort`, `uncaptured error`, `memory access out of bounds` | провал |

Коды возврата: `0` — вердикт `ok`, `1` — `fail`/нет `first-frame`/движок не
остановился.

Полезные флаги:

| Флаг | Зачем |
|---|---|
| `--screenshot out.png` | сохранить кадр (посмотреть глазами) |
| `--frames N` | сколько кадров прогонять до остановки |
| `--chrome <путь>` | если Chrome не в стандартном месте |
| `--keep-artifacts` | оставить профиль браузера для отладки |

## Чего здесь пока нет

* проверки **звука** (звук в веб-сборке собирается, но headless-браузер его не
  воспроизводит);
* автоматической семантической проверки **интерфейса**: RmlUi уже работает
  в веб-сборке; HUD и реплики Re2D проверены в Chrome, но браузерного моста
  к `engine.ui` для проверок элементов пока нет;
* прогона `tests/agent/*` в браузере: агентский протокол идёт по stdin/stdout,
  которыми страница не располагает — нужен мост на WebSocket (описан в
  [docs/WEB_EXPORT.md](../../docs/WEB_EXPORT.md) как следующий шаг).
