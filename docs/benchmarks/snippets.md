# Замер сниппетов (ТЗ §16.5)

`python3 tools/bench_snippets.py --ns 100,500,1000,2000 --frames 120 --json docs/benchmarks/snippets.json`
— macOS arm64, xmake release, прогрев 40 кадров, окно 120 кадров, `--fixed-dt`.
На каждом враге: `ai.chase` + `health.base` + `health.regeneration`.
Время — зона профайлера «JS: логика», мс на кадр.

| N | без поведения | вручную (`$.update`) | сниппеты |
|---|---|---|---|
| 100 | 0.46 | 1.35 | 1.36 |
| 500 | 0.57 | 2.29 | 2.65 |
| 1000 | 0.99 | 3.21 | 3.48 |
| 2000 | 1.02 | 5.15 | 5.83 |

До оптимизаций на N=500 сниппеты стоили 8.55 мс (ручной код 2.43). Изменения:

1. `$.updateFor` создаёт обёртку узла один раз на подписку, а не каждый кадр.
2. Generated JS: одна таблица привязок и один `$.update` на файл; живой
   привязанный узел проверяется флагом `removed`, поиск по id — только без узла.
3. `ai.chase` ищет цель по селектору только когда прежняя исчезла — это дало
   основную разницу (8.55 → 2.36 мс).

Остаток: 81 пакет ещё ищет `$(config.actor|player|target…)` каждый кадр; для
горячих поведений (сотни экземпляров) — кэшировать так же, как `ai.chase`.
Перенос в C не нужен: после правок цена на уровне ручного JS.
