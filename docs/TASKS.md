# Текущие задачи и ограничения R2D

**Курс движка: цель — первая продакшн-игра, 2D-платформер.** Базовый движок
после FINAL ENGINE PASS считается feature-complete; новые engine-level
возможности принимаются только по правилам [FEATURE_FREEZE.md](FEATURE_FREEZE.md).
RE2D / Real2D / RotSprite / Re2D World — не путь этого движка: они не удаляются,
но уезжают за опцию сборки `R2D_ENABLE_RE2D` (по умолчанию `ON`; `OFF` —
сборка платформера, см. [BUILD.md](BUILD.md) и [PHILOSOPHY.md](PHILOSOPHY.md) §1).
Из SDK вырезан 3D-авторинг (см. [SDK.md](SDK.md)). Пункт §3 ниже про Re2D World —
историческая сверка: он не входит в текущий план работ.

Список ниже — только реальные текущие задачи. Справочник поведения —
[HIGH_LEVEL_API.md](HIGH_LEVEL_API.md) и [highlevel/](highlevel/). История —
Git и [CHANGELOG](../CHANGELOG.md); закрытое не висит здесь как «текущий gap».

## 0. Программа производственной готовности

Полная инженерная спецификация — [PRODUCTION_READINESS.md](PRODUCTION_READINESS.md)
(лицензия та же). Она задаёт контракты и критерии приёмки production-ready
ревизии. Сверка фактического состояния — [FEATURE_FREEZE.md](FEATURE_FREEZE.md).

## 1. Запросы и диагностика

Закрыто (2026-10-20): `within` / `nearest` / `inside` / `visibleFrom` /
`limit`, `query` / `inspect` / `profile`, `$.watch`, `$.expect`,
record/replay с checkpoints и state hash, `$.trace` с категориями, фильтром
по селектору, экспортом и чтением агентом. Не возвращать их в список
отсутствующих.

Осталось:

* **`why`** — только как фактическая диагностика (события/контакты/hash), без
  выдуманных объяснений; отдельной «объяснялки» не будет.
* **C-формат CLI-реплея** теперь несёт `content` ID и native-checkpoints
  Box2D (`--checkpoint`, strict/off, exit 3 на расхождении); JS-узлы ему не
  видны — для них `$.replay` v2. Открытых пунктов нет.

## 2. DevTools и UI

`$.devtools` — RmlUi-инспектор и панели. Есть: 15 вкладок F1, инспектор F2,
picking (`.pickMode/pickAt`), безопасные правки `x/y`, `visible/enabled` и
документированных physics-полей, ресурсы/бюджеты в MEM, журнал `$.trace` в
EVENTS, `$.diag.bundle`. ImGui удалён. Legacy `ui.*` / `$.screen` сохранены.

Осталось (не блокирует игру): отдельные визуализации BSP/навигации как
инструмент; файловый `Export override`; правки остальных полей — через API
`$.devtools.set`, не через новые поля формы. Экран загрузки — RmlUi.

## 3. Re2D World

Реализованы XY BSP, вертикальные spans, same-XY многоэтажность, порталы с
экранными окнами и обходом BSP, слитые поверхности, материалы, нативный свет и
тени, туман, декали, панорамное небо (PNG или EXR), точная глубина samples
Re2DSprite, GPU-путь SDL_GPU с CPU-эталоном и World audio (HRTF). Остались:
автоматическая топология cells, непрерывные slopes как физические примитивы,
sweep/полный footprint, прохождение звука через материалы и реверберация.
SDK генерирует лестницы и ступенчатые slopes; это не новые физические примитивы.
Границы — [re2d/RE2D_WORLD_RUNTIME.md](re2d/RE2D_WORLD_RUNTIME.md); измерения —
[RE2D_WORLD_PERF.md](RE2D_WORLD_PERF.md).

## 4. SDK

Закрыто (2026-10-20): граф зависимостей ассетов `r2d deps` с
инкрементальной проверкой (кэш `.r2d/cache/assets.json`, рантайм его не
читает), curve-graph в Particle Studio, клик-выбор элемента в RmlUi Studio,
drag-ресайз коллизий и drag зон акустики. CLI/GUI/агент используют один backend.

Закрыто (2026-10-20): Tilemap terrain editor и анимация тайлов (обычный JSON,
JS↔C parity, реальный runtime-preview), RmlUi font faces weight/style
(`$.font.load(...,{weight,style})`, `$.font.faces()`), установленный macOS-пакет.

Осталось:

* **Font kerning точной настройкой** — RmlUi применяет кернинг из TTF; API
  «подкрутить кернинг» не заводится без реальной игры.
* Универсальный FBX-ретаргетинг (ограниченный Mixamo motion-import есть),
  автоматическая метрика source↔Re2D comparison, кисти поверхности — только по
  реальной потребности игры.
* Установленный пакет на Windows: кросс-сборка есть, запуск на целевой ОС в
  этом проходе не выполнялся. **Linux x86_64 временно исключён из локального
  релиза**: Zig-кросс-сборка зависает; Linux-пользователи собирают движок на
  своей ОС (`xmake f -p linux -a x86_64`). Вернуть: `R2D_BUILD_LINUX=1`.

## 5. Поставка и платформы

Канонический релиз — **локальный** `build_and_push` (Xmake: macOS arm64,
macOS x86_64, Windows x86_64), затем пакеты `dist/`, проверки, коммит, тег и
публикация. Linux x86_64 — сборка на целевой ОС (локальная Zig-кросс-сборка
зависает). GitHub Actions — только validation/build/tests, не
второй релизный pipeline; `release.yml` не восстанавливать. CMake остаётся
сборочным/тестовым деревом разработки (Unity C-тесты, `r2d_check`), но не
релизной сборкой.

`dist/` — снимки конкретных версий; свежесть доказывают версия и checksum
manifest, а не наличие каталога. Нельзя обновлять только AGENTS.md старого
пакета и выдавать это за новый runtime. Фактический результат проверяется
запуском распакованного пакета вне checkout.

Текущее состояние (2026-10-20): macOS arm64 — сборка и пакет проверены; полный
прогон Unity/JS/agent — зелёный; Windows требует проверки на целевой системе;
Linux собирается пользователем на Linux. Web/WASM — отдельно, не считается
готовым по наличию опции.
См. [RELEASING.md](RELEASING.md).

## 6. Правило сопровождения

Закрытый пункт удаляется из текущего списка в том же изменении. История багов
живёт в Git и CHANGELOG. Новое поведение одновременно получает документацию
и подходящую проверку; успешная сборка не заменяет визуальную проверку импорта.
Архитектурные ограничения — [PHILOSOPHY.md](PHILOSOPHY.md).
