# Агент в Editor

Вкладка **Агент** в нижней панели Editor (`Cmd/Ctrl+Shift+A`): журнал в виде чата — ваши сообщения, ответы модели и строки
вызовов инструментов с иконкой и статусом (клик раскрывает результат); запись и операции студий показываются карточкой
подтверждения с диффом; подключение (провайдер, адрес, модель, ключ) — по кнопке настроек; журнал сам прокручивается вниз
(`doc.scroll`, новый метод обёртки документа RmlUi). Ввод — `Ctrl/⌘+Enter`.

**Настройки агента** — отдельная вкладка нижней панели: карточки провайдеров, адрес, модель, ключ, кнопка
«Проверить подключение» (один короткий запрос без инструментов, показывает время ответа или текст ошибки),
лимит шагов на вопрос и переключатель маскота.

**Маскот «Руси-чан»** живёт справа от чата и показывает, что делает агент: думает (`?`), ищет, читает файлы (коробка),
пишет код (ноутбук), проверяет (ключ), ищет (карта, идея с лампочкой), ждёт подтверждения («Можно?»), радуется
(галочка, сердечки) или показывает предупреждение при ошибке; через 45 секунд покоя засыпает, по клику реагирует репликой. Та же анимация идёт в маленькой
иконке на вкладке «Агент», так что работу видно и при открытой другой вкладке. Спрайты — ваш лист
[assets/mascot/sheet_alpha.png](../assets/mascot/sheet_alpha.png), нарезанный `tools/mascot_slice.py` (64 кадра, атлас 156×156,
`editor/ui/mascot.png|rcss|json`; исходный лист с фоном-шахматкой — `assets/mascot/sheet.png`, режется через grabCut); поведение — чистый модуль `editor/lib/agent_mascot.js`.
Перегенерация: `python3 tools/mascot_slice.py assets/mascot/sheet_alpha.png --out editor/ui` (нужны pillow, opencv, numpy).
Лист с прозрачностью режется по неравномерной сетке (границы строк ищутся по проекции альфы), чужие обрывки на краях ячеек удаляются.

Нижняя панель **Агент** — маленький харнес «модель ↔ инструменты» прямо в Editor.
Логика — [editor/lib/agent_harness.js](../editor/lib/agent_harness.js) (чистый модуль,
сеть и инструменты приходят снаружи), оболочка RmlUi — `editor/lib/agent_panel.js`.

## Подключение

Вкладки-провайдеры, поля «адрес», «модель», «ключ»:

| Провайдер | Адрес по умолчанию | Ключ / авторизация |
|-----------|--------------------|--------------------|
| Anthropic (Messages API) | `https://api.anthropic.com` | API-ключ → `x-api-key` |
| OpenAI-совм. (`/chat/completions`) | `http://localhost:8080/v1` (llama-server, Ollama, LM Studio…) | `Bearer`, по необходимости |
| DeepSeek | `https://api.deepseek.com` | `Bearer`, модель `deepseek-flash` (по умолчанию) или `deepseek-v4-pro`; список — `GET /models` |
| OpenCode Go | `https://opencode.ai/zen/go/v1` | ключ из opencode.ai/auth → `Bearer`; харнес сам шлёт `x-opencode-session` (шлюз без него отказывает). Модель из `GET …/models`, по умолчанию `kimi-k2.7-code`. Модели, говорящие по `/responses` или `/messages`, этим провайдером не поддержаны |
| YandexGPT | `https://llm.api.cloud.yandex.net/v1` | API-ключ сервисного аккаунта → `Authorization: Api-Key …`; IAM-токен — введите `Bearer t1.…`. Модель: `gpt://<id каталога>/yandexgpt/latest` |
| GigaChat / GigaCode (Сбер) | `https://gigachat.devices.sberbank.ru/api/v1` | «Authorization key» из кабинета: харнес сам обменивает его на токен (`POST ngw.devices.sberbank.ru:9443/api/v2/oauth`, `scope=GIGACHAT_API_PERS`, `RqUID`) и обновляет по сроку; вызовы инструментов — через `functions` |

Для других российских моделей, говорящих на OpenAI-протоколе (например, через
собственный шлюз), берите «OpenAI-совм.» и свой адрес. Новый вид авторизации —
запись в `PROVIDERS` (`protocol`, `auth`) в `agent_harness.js`.

**Проверено:** DeepSeek (`deepseek-flash`: платформер со счётом и границами мира за 40 с, счёт растёт 0→4) и OpenCode Go (`kimi-k2.7-code`, `glm-5.2`) — вживую (2026-10-22, харнес под Node: цикл с вызовами инструментов, `read_file`/`write_file` отработали). YandexGPT и GigaChat — только юнит-тестами на подставной сети (заголовки, обмен токена, функции), с живыми сервисами не гонялись. Известный риск GigaChat:
его серверы подписаны российским корневым сертификатом; если системное хранилище
curl его не знает, запрос упадёт на TLS — тогда нужен сертификат Минцифры в хранилище
ОС или шлюз.

Ключ хранится **только в памяти** процесса Editor: не пишется в `project.json`,
на диск и в Output. Он уходит лишь в заголовок запроса к указанному адресу.

## Инструменты агента

| Инструмент | Что делает | Подтверждение |
|------------|------------|---------------|
| `docs_search`, `docs_show` | встроенная документация (`r2d docs …`) | нет |
| `list_files`, `read_file` | файлы проекта, только относительные пути без `..` | нет |
| `write_file` | создать/перезаписать файл проекта | **да**, кнопкой «Разрешить» |
| `r2d_lint`, `r2d_validate` | те же native-операции, что у Editor | нет |

Дополнительно (правки — только с подтверждением):

| Инструмент | Что делает |
|------------|------------|
| `search_project` | поиск текста по файлам проекта (как grep): `path:line: текст`, подстрока или регулярка, фильтры `prefix`/`ext` |
| `read_file` (`start`/`end`), `list_files` (`prefix`/`ext`/`limit`), `docs_show` (`start`/`lines`) | чтение по диапазону строк (с номерами) и постраничное — вместо загрузки целиком |
| `delete_file`, `move_file`, `undo_edit` | удаление/перемещение с подтверждением; **любая правка файлов агентом откатывается** (`undo_edit` или кнопка ↶ в шапке панели) |
| `playtest` | сценарий игры headless: `hold`/`tap` клавиш, `frames`, `eval` выражений в игре (позиция героя, текст счёта…) + итоговый кадр (`grid:true` — ASCII-карта 48×18 для моделей без зрения). Проверяет управление, подбор предметов, границы мира |
| `plan` | чеклист плана в панели (pending/doing/done) — для длинных задач |
| `ask_user` | уточняющий вопрос пользователю кнопками вариантов; ответ возвращается агенту |
| `edit_file` | точечная замена фрагмента (`old_string` ровно один раз) — дешевле `write_file`; после записи `.js` lint запускается автоматически, замечания приходят в ответе |
| `api_lookup` | есть ли такой `$`-метод и его аргументы (`r2d docs api`), «такого API нет» — запрет выдумывать |
| `run_check` | короткий headless-прогон игры, возвращает ошибки скриптов |
| `screenshot_check` | headless-прогон N кадров (можно с зажатыми клавишами) → снимок → `r2d image-stats`: `blank: true` — кадр одноцветный/чёрный, иначе яркость, число цветов, доля не-фона. Ловит «игра запускается, но ничего не рисует» |
| `project_info` | `r2d project` |
| `snippet_find` | поиск среди 500 готовых **кирпичиков** (движение, AI, способности, UI, камера…) по слову: id, название, описание, зависимости и поля настройки в одной компактной строке |
| `snippet_apply` | подключить кирпичик к объекту (`owner: object:hero`): граф обновляется, зависимости добавляются сами, значения полей — `values`, затем код генерируется (`snippet generate --write`). Объекты создавайте в коде с `id`. Дешевле и надёжнее, чем писать поведение с нуля |
| `tabs`, `open_tab` | вкладки Editor; файл открывается в своей студии (`.re2dmap` → Hammer, атлас → Atlas, `*.tilemap.json` → Tilemap…) |
| `studio_ops` | какие операции есть у студии вкладки (имена и параметры); вызывать первым в новой студии |
| `studio_state` | состояние и данные документа любой студии (для Hammer — карта); `section` — целый раздел данных |
| `studio_edit` | правка документа **любой студии ассетов** JSON-патчем (RFC 7386) через её историю Undo: tilemap, particles, audio, collision, parallax, fonts, input… |
| `studio_op` | именованная операция студии (аргументы — объект по именам параметров или массив); в Hammer — ещё любые операции native `world-edit` (`brush.create`, `entity.create`, `element.create`, `face.set`, `world.set`…) через сессию карты |
| `studio_save` | сохранить документ студии |
| `editor_op` | операции самого Editor: `new_project` (шаблон + открыть), `open_project`, `run`, `stop`, `validate`, `build`, `reindex`, `create_script`, `create_tilemap`, `create_narrative` |
| `r2d_cli` | любая команда `r2d` (`snippet`, `atlas-grid`, `world-compile`, `story`, `project-set`…): чтение — сразу, команды с записью — с подтверждением |

Так через панель можно собрать игру целиком: `new_project` → скрипты (`write_file`/`edit_file`) → ресурсы в студиях → `validate` → `run_check`. Сквозной сценарий проверяет `tests/agent/editor_agent_panel_test.py` (создание проекта, скрипт, tilemap через студию, сохранение, headless-прогон) — на моканой модели.

**Что не сделано.** Реальные модели планируют такую работу хуже, чем скрипт теста: качество на длинной сборке игры не измерялось. Студии без `ops.edit` (Hammer, Atlas, Narrative, RmlUi, SpriteMesh, Re2DSprite) правятся только их собственными операциями — их список агент берёт из `studio_ops`; полнота этих списков зависит от студии. Подтверждения на каждую запись — осознанное ограничение; режима «разрешать всё» нет.

Старые результаты инструментов сворачиваются (последние 6 целиком), чтобы длинные чтения файлов не оплачивались токенами на каждом шаге.

Лимит — 12 шагов на вопрос; кнопка «Стоп» прерывает цикл.

## Контекст из документации, кирпичиков и API (экономия токенов)

Перед каждым вопросом харнес вызывает `r2d docs context "<вопрос>" --limit 4`
и подкладывает лучшие куски в сообщение — модели реже нужен `docs_search`. Корпус: страницы
документации, **карточки кирпичиков** (`snippets/*/snippet.json`: название, описание, теги, поля) и
записи `$`-API из `api.schema.json`; у каждого куска есть `kind` (`doc`/`snippet`/`api`). Попадание
кирпичика помечается подсказкой «→ snippet_apply». Манифесты кирпичиков вшиты в бинарник
(`tools/embed_bundle.py`); сами каталоги `snippets/` для `snippet add` по-прежнему берутся с диска.

`docs context` работает **гибридно**: BM25 (разбивка по заголовкам, грубый стемминг RU/EN,
стоп-слова запроса) + косинус по эмбеддингам встроенной модели, слияние RRF (k=60);
в ответе `mode`: `hybrid` или `bm25`. Без модели в сборке, с `--no-ai` или `R2D_NO_AI=1`
остаётся чистый BM25.

### Встроенная модель эмбеддингов

* База `intfloat/multilingual-e5-small`, дообучена на парах R2D (документация, `$`-API,
  кирпичики) — см. [AI_TRAINING_CLOUDRU.md](AI_TRAINING_CLOUDRU.md). Экспорт в GGUF:
  `python3 tools/ai/export_gguf.py --model tools/ai/runs/e5-r2d --out models/r2d-embed.gguf`
  (Q4_0, ~70 МБ; на тестовых парах recall@1 0,96, как у f16).
* **В бинарник модель попадает при сборке, если есть `models/r2d-embed.gguf`** (файл не в git):
  `.incbin` (`third_party/ai_model`) + llama.cpp b11669 как локальный xmake-пакет
  (`llama.cpp-r2d`; Metal на macOS). Бинарник растёт с ~29 МБ до ~109 МБ. Нет файла — обычная
  сборка без ИИ-поиска.
* Первое обращение извлекает модель в кэш пользователя (`r2d-embed-<id>.gguf`) и строит
  индекс корпуса (~7400 кусков, около минуты на M4, один раз): векторы лежат в кэше рядом
  (`docs-vec-*.bin`, ~11 МБ), ключ — хеш текстов корпуса и модели. Панель «Агент» прогревает
  индекс при первом показе. Дальше запрос — ~0,5 с.
* `R2D_AI_CPU=1` отключает Metal. Проверено только на macOS arm64; сборки под другие
  платформы с моделью не пробовались.
* Выбор Q4_0 основан на тесте синтетических запросов (описание → карточка) из того же
  распределения, что обучение; на живых вопросах качество не измерялось.

CLI тот же для внешних агентов:

```bash
r2d docs context "как отправить http запрос" --limit 3
```
