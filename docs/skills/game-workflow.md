# Навык: сделать игру целиком

Рабочий цикл от идеи до играбельной сборки. Главное правило: **сначала играбельный вертикальный срез, потом ширина.**
Герой двигается и что-то делает за 5–8 вызовов инструментов; всё остальное — итерации поверх.

## 1. Задача → жанр → набор

1. Если жанр неясен — один `ask_user` с кнопками (платформер / top-down / шутер от первого лица / RPG / головоломка).
2. `skill_load genre-kits` — какие наборы `kit.*` брать под жанр. Затем `skill_load` жанрового навыка
   (`platformer`, `top-down-action`, `fps-2-5d`, `rpg-systems`, `story-dialogue`).
3. `plan` из 5–8 пунктов: герой → мир → цель/враги → HUD → экраны (меню, смерть, победа) → звук/эффекты → проверка.

## 2. Порядок работы (каждый шаг заканчивается проверкой)

| Шаг | Что делаем | Чем проверяем |
|---|---|---|
| 1. Каркас | `new_project` (если проекта нет), `main.js`: `$.ready`, цвет фона, `$.world.gravity/bounds` | `r2d_validate` |
| 2. Герой | объект с `<player>`, `snippet_find`/`snippet_apply` для движения и здоровья (набор `kit.*`) | `playtest`: зажать `D`, позиция героя выросла |
| 3. Мир | платформы `<wall>`, границы, камера; при необходимости карта в студии | `screenshot_check` (кадр не пустой) |
| 4. Цель | монеты/враги/выход: кирпичики `interact.pickup`, `ai.*`, `world.level-exit` | `playtest` с `eval` счёта/здоровья |
| 5. Спрайты | `skill_load pixel-art`, `pixel_art` для героя, врага, тайла, предмета; `.sprite('assets/x.png')` | `screenshot_check grid:true` |
| 6. HUD и экраны | `skill_load ui-hud`: здоровье, счёт, пауза, «игра окончена» | скриншот |
| 7. Ощущения | `skill_load game-feel`, `audio`, `generate-sound`: тряска, вспышка, частицы, сгенерированные звуки | глазами/скриншот |
| 8. Финал | `r2d_lint`, `r2d_validate`, `run_check`, итоговый `playtest` всего пути | всё зелёное |

## 3. Правила, которые экономят шаги

* **Не пиши готовое кодом.** Движение, прыжок, здоровье, оружие, AI, камера, меню — кирпичики. Искать 2–3 раза, потом применять.
* **Делай маленькие правки и проверяй после каждой.** Одна ошибка в 300-строчном файле стоит дороже десяти маленьких шагов.
* **Все объекты для кирпичиков — с литеральным `id`.**
* **Не добавляй то, чего не просили** (магазин, мультиплеер, сохранения) — только если это часть цели игры.
* Нашёл проблему в игре — исправь причину, а не симптом; `undo_edit`, если правка сделала хуже.
* Упёрся в лимит шагов — сохрани состояние: что готово, что осталось (`plan`), и закончи на рабочей игре, а не на половине.

## 4. Критерии «готово»

- [ ] `r2d_validate` и `r2d_lint` без ошибок;
- [ ] `screenshot_check` — кадр не пустой, объекты видны;
- [ ] `playtest`: управление отзывается, цель достижима, проигрыш и победа срабатывают;
- [ ] есть HUD (что я делаю, сколько осталось жизней/очков);
- [ ] у игры есть начало и конец: экран старта или сразу играбельно, экран победы/поражения с перезапуском (`$.scene.restart`).
