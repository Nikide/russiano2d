# Russiano2D Editor

Один бинарник `r2d`: игра, движок, инструменты и редактор. Editor — обычный
проект R2D (`editor/`): интерфейс на RmlUi, логика на публичном `$`, тяжёлые
операции — команды того же `r2d` через мост `$.sdk`. Сцен-редактора нет
(PHILOSOPHY §2): игра остаётся кодом и данными, Editor редактирует и
проверяет обычные файлы проекта.

## 1. Запуск

```bash
./build/r2d                       # Project Manager
./build/r2d edit games/my-game    # сразу открыть проект
./build/r2d --game games/my-game  # запустить игру без редактора
./build/r2d validate games/my-game
```

`src/main.c` разбирает первый аргумент:

| Вызов | Что происходит |
|---|---|
| без аргументов, `edit [проект] [опции]` | `--game <editor> --scene <абсолютный путь проекта>`; опции после проекта идут движку |
| `build --project <dir> …` | нативный билдер (`src/build.c`, [BUILD.md](BUILD.md)) |
| любой другой глагол (`validate`, `lint`, `world`, `assets`, `build <dir> --out`, …) | native tools backend внутри `r2d` (список — `r2d commands`), один JSON в stdout |
| `--опции` | игра/движок, как раньше |

Каталог `editor/` ищется рядом с `r2d` и выше по дереву (в репозитории
`build/r2d` → `editor/`). Путь проекта приходит в редактор как `$.startScene`.
Иконка окна редактора хранится в `editor/assets/icons/russiano2d.png`; проект
может заменить общую иконку, положив свой файл по тому же пути внутри каталога.

## 2. Что умеет (этап 1)

| Часть | Как сделано |
|---|---|
| Project Manager | недавние проекты (`editor/state.local.json`), открыть по пути, создать из шаблона (`r2d templates`, `r2d new`) |
| Дерево проекта | реальные файлы (`r2d assets`), папки сворачиваются, служебные `.r2d-*` не показываются |
| Вкладки | повторное открытие фокусирует вкладку; история назад/вперёд; dirty close предлагает «Сохранить», «Закрыть без сохранения» и «Отмена»; code Save и общие JSON-студии обнаруживают внешнее изменение до записи и предлагают Reload / Overwrite / Cancel; Save All перечисляет документы с отказом в статусе/Output и открывает первую конфликтующую студию |
| Редактор кода | `editor/lib/code_model.js` + `code_view.js`: виртуальная отрисовка JS/JSON/RML/RCSS, автопарные скобки с оборачиванием выделения, умный Enter в `{}`, подсветка парных скобок и `Cmd/Ctrl+Shift+\` для перехода к паре, сворачивание многострочных `{…}` из gutter, Tab/Shift+Tab блока, `Option+↑/↓` переместить строки, `Option+Shift+↑/↓` дублировать, `Cmd/Ctrl+Shift+K` удалить строку, undo/redo, буфер обмена, поиск в файле, переход к строке, автодополнение `$` API и стандартных JS-глобалов/методов (`Tab`/`Enter` принять, `↑`/`↓` выбрать, `Esc` закрыть, `Ctrl+Space` или `Cmd+Shift+Space` вызвать), документация API при наведении, `Cmd/Ctrl+/` — комментарий, `Cmd/Ctrl+D` — следующее вхождение |

Каталог JS-подсказок `editor/lib/js_builtin_catalog.js` генерируется из ECMAScript-деклараций TypeScript 5.9.3 (`lib.esnext.d.ts`); DOM, браузерные API и `Intl` исключены. Обновление: `npm install --prefix /tmp/r2d-typescript typescript@5.9.3`, затем `node scripts/generate_js_builtin_catalog.cjs --typescript /tmp/r2d-typescript/node_modules/typescript`. Редактор использует сигнатуры и комментарии TypeScript, а тип экземпляра выводит для литералов, `new Type()`, простых объявлений `const`/`let`/`var` и распространённых методов-преобразований массивов и строк.

| Problems | `r2d lint` при открытии и сохранении `.js`, native `r2d validate --type json` для несохранённого буфера обычной `.json`-вкладки и `r2d validate` проекта; щелчок открывает файл на строке |
| Run/Stop | Перед `r2d --game <проект>` Editor дожидается Save All для кода и студий ресурсов; при ошибке записи запуск отменяется. Вывод — в Output |
| Build | validate → `r2d build <проект> --out <проект>/dist/<имя>`; ошибки validate останавливают сборку, Output показывает список файлов и итоговые размеры пакета; если backend обрезал чрезмерный журнал, это явно отмечено |
| Inspector | проект (`project.json`; для schema 2 — точка входа и сцены из графа, клик по сцене запускает игру с `--scene`), файл (язык, строки, состояние, проблемы), навигация по `$.scene.add(…)`/`id: …` и контекстная справка с сигнатурой по `$`-символу под кареткой или курсором мыши |

Перед записью dirty-кодового документа Editor сравнивает дисковый текст с
версией, загруженной при открытии или последнем сохранении. При внешнем
изменении можно отменить операцию, загрузить дисковую версию или явно записать
версию Editor поверх неё. Если файл удалён, Editor предлагает только отмену или
явное создание из версии Editor. Проверка покрыта
`tests/agent/editor_external_change_test.py` (8 сценариев).

Вставленная пустая пара скобок или кавычек удаляется одним `Backspace`.

Подсветка JS добавляет смысловые цвета к `$` API из встроенного каталога документации: `$` и пространства имён отличаются от JS, `$('<player>')` выделяет тег создания зелёным, методы создания/добавления — зелёным, удаления (`remove`, `delete`, `destroy` и их варианты) — красным. Для переменных, созданных через `$()`, распознаются задокументированные методы `$.fn`.

**Открыть как.** Файл открывается основной студией своего типа (`.atlas.json` —
Sprite, `.re2dmap` — Hammer, `.rml` — RmlUi). Палитра команд (`>`) для
активной вкладки предлагает «Открыть как: текст» и другие подходящие студии
(Animation, SpriteMesh); студии сами переходят друг к другу тем же
путём (`app.openTool` → `openWith`).

Горячие клавиши: `Cmd/Ctrl+P` — файл, `Cmd/Ctrl+Shift+P` — команды
(префикс `>`), `Cmd/Ctrl+Shift+O` — символы текущего JS-файла, `:` — строка,
`Cmd/Ctrl+S`/`Shift+S` — сохранить/все,
`Cmd/Ctrl+W`, `Cmd/Ctrl+B` — боковая панель, `Cmd/Ctrl+J` — нижняя,
`Shift+F12` — буквальный поиск слова под кареткой по проекту,
`F5`/`Shift+F5`, `Cmd/Ctrl+Shift+B` — сборка, `Esc` — закрыть палитру/поиск.
Клавиши кода работают только при фокусе на коде: поля ввода получают обычный
текст. Поиск слова — текстовые совпадения, не семантический поиск ссылок.
JS-outline перечисляет объявления функций, классов и простые
`const`/`let`/`var` в текущем файле. Это локальный лексический список, а не
межфайловое разрешение символов; деструктуризация и области видимости не
анализируются.

## 3. Чего пока нет (честно)

* Editor загружает студии из `editor/studios/`; общие модели перенесены в
  `editor/lib/shared/`. Старый SDK GUI не входит в Xmake, дистрибутив или
  пользовательский workflow. Native команды редактора собираются в `r2d`
  из `sdk/native/` и не являются отдельным приложением;
* RmlUi-предпросмотр не подсвечивает выбранный элемент поверх документа;
* боковая Search ищет буквальный текст в перечисленных `r2d assets` текстовых
  файлах (до 1 MiB каждый и 32 MiB чтения на запрос, максимум 200 результатов)
  и открывает строку; при достижении лимита показывает это в выдаче;
  поиск по бинарным и исключённым `build`/`dist`/`node_modules` путям не выполняется;
* линт несохранённого буфера не делается: Problems отражают файл на диске;
* в редакторе кода незавершённая IME-композиция показывается подчёркнутым
  текстом и вставляется в документ только после подтверждения; положение
  окна кандидатов привязано к каретке. Проверка системного UI кандидатов
  остаётся платформенной GUI-приёмкой.
* JS IntelliSense не является TypeScript Language Service/LSP: поддерживаются встроенные JS-типы, публичный `$` API и простые локальные алиасы; нет семантической навигации, рефакторингов, сниппетов и нескольких кареток.

* Re2DSprite Studio не компилирует поверхности и не печёт PNG: авторский
  конвейер — `tools/compile_rotsprite.py` / `build_rotsprite_assets.py`.
  Команд `bake-re2d3`/`convert-re2d3`, на которые ссылается
  [RE2DSPRITE_GUIDE.md](RE2DSPRITE_GUIDE.md), в `r2d commands` сейчас нет;
* запись `character.json` переформатирует файл (`JSON.stringify`, 2 пробела).

## 4. Устройство

**Каркас студий** (`editor/lib/studio_kit.js`, реестр `editor/studios/index.js`).
Студия Editor — модуль с `meta` и `create(host)`; экземпляр на вкладку со
своим документом (`$.ui.markup`, разметка `editor/ui/studios/<id>.rml` +
общий `kit.rcss`), поэтому два атласа или две карты открыты одновременно.
Editor сам размещает документ, зовёт `update(dt)` только у активной вкладки,
направляет Cmd/Ctrl+S, Z, Shift+Z, Y в `save/undo/redo` студии (кроме набора
текста — `$.ui.typing()`), собирает `diagnostics()` в Problems и `commands()`
в палитру. Своих `$.update`, горячих клавиш сохранения и кнопок «назад» у
студий нет.


`editor/main.js` → `createEditor($)` (`editor/app.js`). Чистые модули без
движка: `lib/code_model.js` (буфер, каретка, правки, undo), `lib/highlight.js`
(токенизатор), `lib/fuzzy.js` (нечёткий поиск).

Hammer использует модели из `editor/lib/shared/world_editor/`; геометрия остаётся в native `r2d world-edit`. Временные файлы и runtime-узлы preview имеют отдельные имена на сессию. Save/Validate/Compile блокируют параллельные правки своей карты. Ошибка компиляции сохраняет последний корректный файл и runtime preview. Камера preview сохраняет перемещение между кадрами; ввод и позиция sprite учитывают масштаб окна.

Новое в `$` ради Editor:
`$.input.clipboard()/setClipboard()`, псевдонимы `cmd`/`rcmd` по платформе,
`doc.focus(id, on?)` (`engine.ui.focus`), `doc.place(rect)` и `doc.front()`
(`engine.ui.place/front`) — встраивание документа студии в центральную область.
RmlUi отдаёт `src="/abs/path.png"` файловому интерфейсу без ведущего слеша;
`src/gui.cpp` последним вариантом пробует путь с возвращённым `/`, поэтому
документы могут показывать картинки открытого проекта по абсолютному пути.

Студии подключаются в `editor/studios/index.js`: каждой вкладке — свой
экземпляр `create(host)`; `host` даёт `backend` (`r2d <команда>`), `run/stop`,
`status`, `changed`, `openWith`, `typing`, `preview` и `root()` — корень
открытого проекта. Старые id студий ведут к соответствующим студиям Editor через алиасы.
Неактивная вкладка скрыта, `update(dt)` получает только активная, поэтому
клавиши студии не срабатывают из других вкладок; клавиши из `meta.ownKeys`
(Hammer: F5) Editor на её вкладке не перехватывает. Агенту доступна та же поверхность:
`eval("$.editorApp.openFile('main.js')")`.

## 7. Перенос SpriteMesh (2026-10-20)

`SpriteMesh` входит в native-реестр; `sprite-mesh-studio` — алиас `sprite-mesh`.
Контроллер один: прежняя оболочка SDK использует тонкий адаптер. Ввод и
анимация обновляются только у активной вкладки. Viewport переводится из
пикселей RmlUi в логические координаты окна; колесо работает внутри viewport.

Dirty обозначает правки настроек. Отсутствующий или устаревший производный
cache сам по себе не делает документ несохранённым. Apply создаёт временный
cache с отдельным именем на вкладку и удаляет его после чтения, в том числе
при ошибке или закрытии. Undo/Redo помечают показанный preview устаревшим;
пересобрать его можно командой палитры «SpriteMesh: Bake preview».

Save сначала проверяет native bake на временном файле. Неизменённый atlas с уже включённым SpriteMesh
сохраняет исходные байты; первое Save + Bake включает `re2d.spriteMesh`. Правки настроек записываются в `re2d.spriteMesh`;
ошибка публикации cache откатывает источник, сохраняя dirty. Изменённый извне
atlas не перезаписывается. PNG получает только baked cache: отдельного
формата настроек нет, при повторном открытии используются defaults.

Приёмка: `tests/agent/editor_sprite_mesh_test.py` — 36 проверок: независимые вкладки,
историю, сохранность исходников и cache при ошибках, ручной/покадровый pivot,
ракурс спереди, первое включение SpriteMesh, PNG и закрытие pending preview.
Xmake-сборка, native bake/cache test, 6 qjs-тестов SpriteMesh, полный
`sdk_studios_test.py`, lint, validate Editor и четыре стража документации прошли.
Снимок настоящего RmlUi:
`build/editor-sprite-mesh-tabs.png`. Другие ОС и ручной HiDPI-прогон не проверены.


## 8. Re2D World внутри Hammer (2026-10-20)

Карты с cells/walls открываются в обычной вкладке Hammer. Старое имя
`re2d-world-studio` — алиас Hammer; повторное открытие через алиас сохраняет
вкладку, её историю и preview. Отдельная студия World в Editor удалена из
реестра. Старый standalone-инструмент SDK оставлен для совместимости.

Дерево, Select/Move/Delete/Duplicate, инспектор и TOP/FRONT/SIDE работают с
cells, walls, portals, stairs, slopes и lights. Вертикальные spans клетки
показываются отдельно, под одним id. Поля rect/spans/openings редактируются
в инспекторе; раздел «Re2D World» добавляет объекты, редактирует полный JSON
выбранного объекта (включая произвольные поля), разделяет/объединяет стены.
Join требует одинаковых свойств стен, чтобы не потерять материал и теги.

Все правки проходят существующий native `world-edit` и одну историю карты:
например, Undo отменяет brush, следующий Undo — предшествующую правку cell.
Save/Validate/Compile, диагностика Problems и runtime preview общие. PNG
albedo/normal применяется кнопкой «Материал PNG (только preview)»; этот
эксперимент не записывает назначение материала в авторский файл. Debug/CPU/GPU
и свет используют тот же `$.re2dWorld`. Для клетки начальная камера находится
в первом span. Карты не преобразуются в brushes; cell-картам без `world` и
`regionSize` редактор не добавляет конверт и не меняет native defaults.

Проверка объединения: `tests/agent/editor_hammer_world_test.py` — 43 проверки
живого Editor; `tests/js/sdk_world_editor_elements_test.mjs` — 4 проверки

## Стартовый экран

Без открытого проекта Editor показывает стартовый экран. Слева — недавние
проекты: пропавшие папки помечены и идут в конце, «×» убирает строку из

## Тестовые сессии агента

Откройте проектный файл `*.agent.json` и выполните команду палитры «Тесты:
выполнить активную .agent.json сессию». Editor сохраняет открытые документы и
передаёт сессию существующей native-команде `r2d agent`. Структурированный
отчёт, ответы runtime и пути доступных артефактов остаются в Output; число
неуспешных запросов видно в строке состояния, а диагностики backend попадают
в Problems. Если backend не вернул отчёт, Editor показывает это отдельно и не
придумывает причину отказа. Приёмка: `tests/agent/editor_agent_session_test.py`
(6 проверок на команду палитры, успешную сессию и отказ runtime-запроса).

## Окна выбора файла и папки

Везде, где Editor просит путь, открывается окно ОС (`$.fs.pickFolder` /
`pickFile` / `saveFile`, [store.md](highlevel/store.md)):

| Где | Что |
|---|---|
| Стартовый экран | «Открыть проект…», «Изменить…» (куда создать) |
| Палитра | «Проект: открыть папку…», «Файл: открыть с диска…», «Проект: собрать в папку…» |
| Tilemap / Particles / Audio | «…» у полей тайлсета, текстуры, файла звука |
| Audio / Fonts / Parallax | «+ … из файла…» в библиотеке; «…» у `src` спрайта |
| Narrative | «…» у ассета и голоса, «Новая сцена…» (окно «Сохранить как») |

Пути ассетов хранятся относительно проекта; файл вне проекта не берётся —
диагностика `EDITOR_ASSET_FILE` (в Narrative — `SDK_VN_PATH`) с подсказкой
положить его в проект. Отмена ничего не меняет. Приёмка:
`tests/agent/editor_file_dialogs_test.py` (9 проверок; окно ОС подменяется).
