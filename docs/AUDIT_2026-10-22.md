## Открытые баги (не исправлены)

### Высокий приоритет

* **C-тесты SDK не запускаются вообще** (`tests/sdk/*.c` — 6 файлов, плюс `tests/re2d/brush_advanced_fixture_test.c`,
  `sky_leak_test.c`). После ухода с CMake они нигде не собираются; `docs/SDK_VERIFICATION.md`
  всё ещё ссылается на `cmake --build ... r2d_sdk_core_test`. Попытка подключить через `test_target`
  упёрлась в зависимость SDK от всего движка (`render.h` → `quickjs.h`, stb, zlib, defines `R2D_HAVE_SDK`).
  Нужен общий `static`-таргет `r2d_sdk_lib` либо запуск тестов как part of `r2d`.
* **`re2d_gta_combat_test`**: смертельное попадание даёт узлу событие `'damaged'` **дважды**
  (счётчики `2/1` вместо `1/1`). `.damage()` эмитит `damaged` один раз (`api.js:2076`), второй эмит
  идёт откуда-то из боевого пути (`combat.js`/hit). Не разобрано до конца; тест падал на HEAD.
* **Тесты на удалённый legacy-SDK**: `sdk_studios_test` (`sdk/templates/ui-menu` удалён коммитом
  `6fb7dbba`), `sdk_shell_test`, `sdk_splash_test`, `editor_output_test` — падают. Нужно либо
  портировать на Editor, либо удалить.

### Средний приоритет

* `bashnya_visual_refs_test`: «BASHNYA start has no script errors» — в игре bashnya есть
  ошибка скрипта при старте (кадры и скриншоты в норме).
* `r2d validate demos/re2d_npcs`: 5 из 6 `*.character.json` (assault, scout, commander, heavy,
  sniper) ссылаются на отсутствующие `*.png`/`*.surface.json` (есть только medic). Демо с битыми ссылками.
* `r2d validate demos/real2d`: 13 × `R2D100` на `BODY_ASSET_REPORT.json` — ссылки в отчёте
  резолвятся от корня проекта, а не от `assets/` (вероятно ложное срабатывание валидатора, или
  отчёт лежит не там).
* `demos/re2d_visual_lab`: нет `main.js` (`R2D100`).
* `build_test`: ожидает `demos/` рядом с бинарником xmake-сборки — путь релизной раскладки
  не воспроизводится в `build-xmake/...`.
* HTTP (`http.c`): `getaddrinfo` синхронный в основном потоке (подвисание кадра на медленном DNS);
  заголовки разбираются только в первых 4096 байтах (`head_text`) — `Transfer-Encoding: chunked`
  за этой границей не будет найден; пробелы в пути URL не отклоняются; IPv6-литералы и
  `user@host` в `r2d__parse_http_url` не поддерживаются.
* `net.c`: `r2d_net_open(port)` после неявного клиентского `r2d_net_connect` возвращает ошибку
  «транспорт уже открыт на порту 0» — клиент не может стать сервером без перезапуска.
  `enet_address_set_host` тоже блокирующий.
* Аудио/HRTF-тесты (`audio_hrtf_test`, `re2d_world_audio_test`, `re2d_dust2_props_audio_test`):
  «HRTF backend unavailable» — вероятно зависят от окружения (нет аудиоустройства в headless);
  тесты должны `skip` с причиной, а не падать.

### Низкий приоритет

* `fs_util.c`: `r2d_fs_write_atomic` не делает `fsync` каталога после `rename` (durability
  при потере питания); `temp_path_for` молча усекает путь >4096; `static char win[256]` в
  `set_error` (Windows) не потокобезопасен.
* `$.store` без `engine.fs.writeAtomic` оставляет `*.tmp` навсегда (поведение закреплено тестом
  `save_schema_test`, но на диске копится мусор; в корне репозитория лежат `save.json.tmp`,
  `settings.json.tmp`).
* `tests/embed_sync_test.py`: таблица `simple` разбирает `\0` раньше восьмеричных escape —
  `\033` прочитается как `\0` + `33`. Генератор восьмеричных не выдаёт, но тест хрупкий.
* `real2d4.c`: `p += nlen+elen+clen` может уйти за `cd_end` (UB арифметики указателя до следующей
  проверки `p + 46 > cd_end`).
* `tests/agent/results/huge_scaling.csv` и `re2d_huge_scaling_report.json` отслеживаются git и
  переписываются при каждом прогоне тестов — рабочее дерево грязнится. Вынести в игнор/артефакты.
* Мёртвый код: `task("js_test")` в `xmake.lua` недоступен из CLI (нет `set_menu`; `xmake js_test` →
  `invalid task`); JS-тесты реально идут через `xmake test` (цель `js_tests`).
* Предупреждение компилятора `src/script.c:192`: `/*` внутри блочного комментария (`r2d/*`).
* Битые ссылки в `docs/internal/NATIVE.md` и `DEPENDENCY_DECISIONS.md` на `cmake/*.cmake`.
* `.claude/skills/r2d-engine/SKILL.md` (не в git) всё ещё велит `cmake --build build` и
  «не коммитить без просьбы» — расходится с `AGENTS.md` (xmake).

## Предложения по улучшению

1. **Единый быстрый слой проверок.** `tools/run_tests.py --fast` существует, но доки называют
   несуществующий `ci_verify`. Описать в `TESTING.md` один «быстрый» набор (xmake test + `--fast` +
   три стража доков) и запускать его в CI на каждый коммит.
2. **Статический страж «тест подключён к сборке»** для *всех* `tests/**/*.c`, а не только
   `tests/re2d` (`tools/test_layout_check.py` сейчас видит лишь последний каталог) — иначе
   пункты 6 и «SDK-тесты» повторятся.
3. **Skip вместо fail для окружения** (аудио, GPU, `demos/` рядом с бинарником) с явным кодом
   причины; 11 skip в прогоне тоже стоит разобрать — «пропуск не считается успехом».
4. **Параллельный запуск `run_tests.py`**: полный прогон ≈18 мин последовательно; тесты
   независимы (отдельные процессы Agent), нужен `-j N` с отдельными рабочими каталогами.
5. **Асинхронный DNS** (поток или `getaddrinfo_a`) в HTTP/ENet, чтобы не блокировать кадр.
6. **Единый путь генерации**: тесты, читающие `build*/generated/...`, должны получать путь от
   xmake (переменная окружения `R2D_GENERATED_DIR`), а не угадывать каталог.
7. **Перенести результаты бенчмарков** `tests/agent/results/` из git в артефакты CI.
8. **Фаззинг** парсеров `payload.c`, `json.c`, `real2d4.c` (контейнер) — код аккуратный, но
   входы недоверенные (игры/ассеты из сети); libFuzzer-цели дёшевы при уже собранных ASan-тестах.
9. **Валидатор демо в CI**: `r2d validate` по каждому `demos/*`, чтобы битые ссылки
   (`re2d_npcs`) не копились.
