# VFX: чего не хватает и каким будет `r2dvfx`

> Рабочий документ. Не публикуется на сайте (allow-list сайта — только `$`-дока,
> CHANGELOG и туториалы). Решение по Effekseer — `docs/internal/DEPENDENCY_DECISIONS.md`.

Собрано по итогам сессии: отчёт BASHNYA (разделы E, F, H, I), наши собственные
замеры и разбор смены сцены. Пункты с пометкой **«дефект»** — расхождение с
ожиданием; **«пробел»** — отсутствующая возможность, которую просят игры.

---

## A. Смена сцены: чего нет

Сейчас: `$.scene.load(name)` ставит запрос, смена происходит в начале
следующего кадра; переход `fade` 300 мс (две фазы out/in); звук уходящей сцены
снимается ДО `exit()` с затуханием (250 мс, `{audio_fade}`, `{keep:true}`);
`load(name, {scope:true})` снимает только область прошлой сцены; генерации
переходов защищают от гонок.

| # | Чего нет | Как должно выглядеть | Приёмка |
|---|---|---|---|
| A1 | **экрана загрузки с прогрессом** (`loadAsync`/`preload` есть, канваса нет) | `$.scene.loadAsync(name, {progress: true})` отдаёт `{total, done, ready}`, плюс штатный `<ui.panel>`-оверлей с полосой, который игра может переопределить | прогресс ползёт по реальным шагам (ассеты/скрипты/атласы), а не по таймеру; числа в тесте: сколько шагов, сколько мс |
| A2 | **переходов кроме fade** (диагональ, шторка, шахматка, shader-переход) | тип перехода описывается спекой (`{type:'wipe', dir, soft}`, `{type:'shader', name, params}`) и идёт нашим пост-проходом, без остановки мира | визуальный эталон на кадре; переход не тратит больше 1 мс на кадр при 1080p |
| A3 | **автосброса глобального света и затемнения** (I14, **дефект**) | при смене сцены `resetFx` сбрасывает световую карту, затемнение мира и состояние эмиттеров; игра может запретить (`{keep_light:true}`) | замер до/после: двойное затемнение исчезает, «свет прошлой сцены» не переезжает; тест падает на старом коде |
| A4 | **отмены перехода посередине** с восстановлением (сейчас только «новый load побеждает старый» через generation) | `$.scene.cancel()` откатывает начатый переход: мир остаётся прежним, затемнение снимается за остаток времени, `busy()` корректно гаснет | N быстрых `load`+`cancel` подряд: мир прежний, затемнение 0, сцена консистентна |

### A0. Улучшить сам переключатель сцен (запрос владельца)

Сейчас переключатель минимальный: `load()` откладывает запрос, `fade` без настройки,
рапидные `load` выигрывает последний, ошибок лоадера сцена не различает.
Что улучшаем — без новых «сущностей», одной точкой входа:

| # | Улучшение | Как | Приёмка |
|---|---|---|---|
| A0.1 | **одна точка входа** `$.scene.change(name, opts)` | опции: `{transition, loading, audio_fade, keep_light, timeout_ms, min_loading_ms}`; старый `load()` остаётся как тонкая обёртка (совместимость) | `load` и `change` дают одинаковый результат на одинаковых опциях; старые вызовы не ломаются |
| A0.2 | **склейка рапидных запросов** | N вызовов в одном кадре — один переход на последнюю сцену, без мигания и двойного затемнения | N=5 подряд в одном кадре → ровно 1 переход, 0 промежуточных `enter`, затемнение монотонное |
| A0.3 | **интроспекция перехода** | `$.scene.state()` → `{from, to, phase:'out'|'load'|'in', t, ratio, pending, prepared}` | во время перехода поля отражают факт; после — `phase:null`, `busy()===false` |
| A0.4 | **события жизненного цикла** | `scene:before-change`, `scene:progress`, `scene:after-change`, `scene:error` | подписки получают по одному событию на переход; при падении лоадера — `scene:error` и возврат к прежней сцене |
| A0.5 | **ошибка загрузки не оставляет пустой мир** | лоадер упал → мир прежней сцены цел, затемнение снято, сцена остаётся прежней, ошибка в журнал и в `$.debug.errors()` | симулируем падение загрузки: прежняя сцена жива (ноды на месте), `scene:error` пришёл |
| A0.6 | **подготовка и мгновенное переключение** | `$.scene.prepare(name)` (заранее) + `$.scene.promote(name)` (мгновенно, без загрузки); можно prefetch следующей сцены, пока текущая играется | подготовленная сцена переключается **без** экрана загрузки: замер времени переключения (мс) против обычного пути |

### A1 (расширено). Встроенный прогресс-бар + свой RmlUi на экране загрузки

Требование владельца дословно: **«сделать внутри движка простой прогресс-бар и давать
метод для смены сцены с загрузкой + возможность поставить на сцену загрузки свой rml»**.

| Часть | Как |
|---|---|
| **встроенный прогресс-бар** | штатный `<ui.panel>`-оверлей с полосой и подписью; по умолчанию включён, стилизуется через `$.scene.loading({style:{...}})`; рисуется **над** миром, но **под** диалогами, и не тикает вместе с миром |
| **источник прогресса** | реальные шаги лоадера: ассеты/скрипты/атласы/сцены; `loadAsync(name, {progress:true})` отдаёт `{total, done, ratio, label}` и `onProgress(done,total,label)`; полоса использует `ratio`, подпись — `label` |
| **свой RmlUi на экране загрузки** | `$.scene.loading({rml:'ui/loading.rml', theme:'ui/loading.rcss', min_ms:300, timeout_ms:15000})`; документ получает данные прогресса (`progress=demo.…`/data-атрибуты или `$.ui.doc().set('progress', ratio)`), игра может рисовать хоть свои арты и анимацию |
| **правила** | `min_loading_ms` — против мигания (быстрая загрузка всё равно показывает экран N мс); `timeout_ms` — понятная ошибка вместо вечного экрана; мир на время загрузки паузится, звук глушится (кроме `{keep:true}`) |
| **приёмка** | (1) медленный лоадер: прогресс растёт **монотонно**, кадр не рвётся, экран виден ≥ `min_loading_ms`; (2) кастомный `.rml` реально отображается (проверка по id через `layoutRect`), а без настройки используется встроенный; (3) `timeout` даёт ошибку и возврат к прежней сцене; (4) числа: шагов всего/выполнено, время загрузки, время перехода |

## B. Свет, тени, эмиттеры: что добавить

| # | Пункт | Суть | Приёмка |
|---|---|---|---|
| B1 | **I12 — динамика эмиттера** (пробел) | у эмиттера нет мерцания/анимации интенсивности: сейчас только статичное `intensity` | `emissive({flicker: {hz, depth, curve}})` или дорожка `intensity` во времени; замер: интенсивность по кадрам совпадает с заданной кривой, стоимость ≤ 0.02 мс на 1000 эмиттеров |
| B2 | **I11 — бюджет и LOD света/теней** (пробел) | игра прореживает источники руками; у движка нет бюджета | `$.gfx.light.budget({max, priority, radiusScale})`: при превышении лимита дальние/слабые источники понижаются в LOD или гасятся, и это **слышно** (счётчик `degraded`, отчёт в `qualityReport()`); замер: 45 эмиттеров при лимите 32 → 32 полных + 13 degraded (у нас уже есть такой замер — закрепить бюджетом) |
| B3 | **I14 — двойное затемнение и глобальное состояние света** (дефект) | состояние света переживает смену сцены, затемнение применяется дважды | закрывается вместе с A3; отдельный тест: смена сцены → свет/затемнение в исходном состоянии |

## D. `r2dvfx` — своя VFX-библиотека вместо Effekseer

**Решение:** Effekseer не встраиваем (`docs/internal/DEPENDENCY_DECISIONS.md`:
ядро 187 файлов / 46 033 строки, 53 виртуальных метода, 0.11 мкс на частицу,
готовый бэкенд закрыт отсутствием нативных хендлов в SDL 3.4.0). Вместо него —
**свой набор эффектов `r2dvfx`**, собранный из того, что у движка уже есть, плюс
**композиция прямо из кода**: новые эффекты делаются соединением существующих, а
не переписыванием с нуля.

### D1. Модель эффекта

Эффект — **слои во времени**, а не один вызов. Спека декларативная (данные, не
код), поэтому её можно хранить в файле, править в инспекторе и сериализовать:

```js
$.vfx.define('hit.spark', {
    duration: 0.35,
    budget: { particles: 120, light: 1 },   // для I11
    seed: 'hit',                            // детерминизм (важно для гейтов)
    layers: [
        { at: 0.00, use: 'particles.burst', params: { count: 24, speed: [80, 220], life: [0.2, 0.4], color: '#ffd27a' } },
        { at: 0.00, use: 'fx.flash',        params: { color: '#fff3c4', alpha: 0.6, ms: 90 } },
        { at: 0.00, use: 'fx.hitStop',      params: { ms: 40 } },
        { at: 0.00, use: 'fx.shake',        params: { amp: 3, ms: 120 } },
        { at: 0.00, use: 'light.emitter',   params: { color: 'auto', radius: 220, intensity: 1.2, flicker: { hz: 12, depth: 0.3 } } },
        { at: 0.02, use: 'fx.ribbon',       params: { width: [6, 0], life: 0.18, color: '#ffb46b' } },
        { at: 0.10, use: 'sound.playBank',  params: { bank: 'hit.metal', pitchRange: 0.9 } },
    ],
});
```

Примитивы `use:` — **ровно то, что уже есть** в движке (это и есть «соединяй
существующее»): `particles.preset`, `particles.burst`, `fx.flash`, `fx.shake`,
`fx.hitStop`, `fx.shockwave`, `fx.lightning`, `fx.pulse`, `fx.ribbon`,
`fx.trail`, `fx.attractor`, `light.emitter`, `sound.playBank`, `shader.<имя>`,
`layers.fadeTo`, `clip.<имя>`.

### D2. Композиция из кода

```js
// собрать новый эффект из существующих частей
const big = $.vfx.extend('hit.spark', {
    duration: 0.6,
    layers: [{ at: 0.15, use: 'fx.shockwave', params: { radius: 320 } }],
});

// проиграть с вариацией и привязкой
const h = $.vfx.play(big, { at: [x, y], parent: node, follow: node, rate: 1.2 });
h.stop();  h.seek(0.2);  h.setRate(0.5);  h.query();   // состояние и управление

// разово, без регистрации
$.vfx.spawn(node, { duration: 0.2, layers: [{ at: 0, use: 'fx.flash' }] });
```

Правила: спека — **чистые данные** (никаких замыканий), эффект **детерминирован
по `seed`** (для гейтов и повторов), `$.vfx.extend` не мутирует базу, `play`
возвращает хендл, время идёт по игровому `dt` (пауза останавливает эффекты).

### D3. Что входит в набор (первый релиз)

Удары: `hit.spark`, `hit.metal`, `hit.soft`, `crit`;
движение: `jump.dust`, `land.dust`, `dash.wind`, `footstep`; 
мир: `torch.flame` (с мерцанием — B1), `campfire`, `magic.circle`;
боёвка: `explosion`, `shockwave`, `slash`, `parry`;
сцена: `fade`, `flash.screen`, `quake`, `slowmo`;
сигналы: `pickup`, `quest.done`, `warning`.

**Число примитивов ≥ 40, число готовых эффектов ≥ 20** — это ответ на
«набор множества VFX».

### D4. Милстоуны

| M | Что | Приёмка |
|---|---|---|
| **M1** | реестр + примитивы + `play/spawn/stop/seek` | 20 эффектов работают на фикстуре; хендл управляет эффектом; `api_freeze` + доки |
| **M2** | `define/extend` + валидация спеки (неизвестный примитив → понятная ошибка, не тишина) | тест: опечатка в `use` отклоняется со списком допустимых; `extend` не мутирует базу |
| **M3** | бюджет/детерминизм: спека несёт `budget`, `seed`; эффекты попадают в общий счётчик частиц (вместе с B2) | замер: 100 одновременных эффектов не выбивают бюджет; два прогона с одним `seed` дают одинаковый кадр (хеш) |
| **M4** | авторский контур: предпросмотр эффекта во вкладке DevTools (список, прогресс, перемотка), экспорт спеки в JSON | визуальная проверка; экспорт→импорт даёт идентичный эффект |
| **M5** | клипы и VFX: примитив `clip.<имя>`; эффекты на кадрах без ручных списков | эффект на клипе из двух листов играет; доки |

### D5. Чего `r2dvfx` НЕ делает (границы)

- **не** замена `$.particles` — это надстройка над ним;
- **не** редактор с графами (в M4 — список и перемотка, не нодовый граф);
- **не** тянет внешние форматы (никаких `.efk`/Effekseer-совместимости);
- **не** обещает 3D: только 2D-спрайты, ленты, свет, экранные эффекты.

### D6. Риски

| Риск | Митигация |
|---|---|
| спека станет «языком» и задушит гибкость | спека — данные для типового; всегда есть `$.vfx.spawn` с кодом и прямой доступ к примитивам |
| детерминизм ломается от `dt`/кадра | используем игровое время, `seed` в спеке, хеш кадра в тесте |
| стоимость эффектов в кадре | бюджет частиц и `stats()`: `$.vfx.stats()` — сколько активных эффектов/частиц/эмиттеров |
| дублирование с `$.hits`/`$.fx` | `$.hits` остаётся пресетами попаданий, `$.vfx` — авторингом; `use:` ссылается на те же низкоуровневые вызовы |

## E. Граница: публичное API — только `$` (high-level)

**Правило владельца (уточнено):** API вне `$` делать НЕЛЬЗЯ. Публичная поверхность
движка — только high-level и только в `$`; отдельного низкоуровневого `r2dvfx`-модуля,
глобала или «второй витрины» не существует. Ранее записанный здесь раздел был неверно
понят как запрос — это ограничение, а не хотелка.

### E1. Что из этого следует для `r2dvfx`

| Вопрос | Ответ по правилу |
|---|---|
| Как игра создаёт и играет эффекты | только `$.vfx.define/extend/play/spawn` — one public surface |
| Как загружать спеки из файлов | `$.vfx.load(path)` / `$.vfx.loadAll(dir)` **внутри** `$`; отдельного `r2dvfx.load` нет |
| Можно ли звать эффекты из C/нативных тулов | нет публичного `engine.vfx.*`; C-уровень остаётся **внутренним** (как остальные `engine.*`-биндинги), документируется только `$`-поверхность |
| Инструменты (валидатор, предпросмотр) | это **build-time тулы**, а не runtime API: `tools/r2dvfx_check.py`, `tools/r2dvfx_preview.py`. Они читают те же спеки, но игрой не вызываются и в заморозку API не входят |

### E2. Как это проверяется

- **заморозка API** (`api_freeze`) фиксирует только `$`-поверхность: появление
  `r2dvfx.*` или `engine.vfx.*` как публичных имён — нарушение правила, а не фича;
- **док-гейт** (`api_docs_sync`): каждое новое публичное имя обязано быть в `$`-доке;
- **в ревью**: любая правка, добавляющая «точку входа вне `$`» для игр, отклоняется;
  исключение — build-time тулы (не поставляются как API и не документируются в
  `HIGH_LEVEL_API.md`).

### E3. Почему так

1. **одна точка входа — одна документированная поверхность** (у нас уже 3125 имён в `$`,
   второй namespace удвоил бы поддержку и размыл заморозку);
2. **все правила `$` работают и для эффектов**: правило промаха цели, дедупликация
   сообщений, детерминизм по `--seed`, ошибки в `$.debug.errors()`;
3. **игроку не нужно знать про C-уровень** — это внутренняя реализация, а не контракт.

## F. Разделение `$.fx` → `$.sfx` + `$.vfx` (запрос владельца)

**Проблема:** сейчас `$.fx` — «для всего»: удары, вспышки, тряска, hit-stop, ленты,
молнии, притяжение, статистика, а внутри `impact`/`$.hits` ещё и звук. Имя `fx` не
говорит, что слышно, а что видно.

**Правило раздела (простое, проверяемое):**

> **Что слышно → `$.sfx` (sound effects). Что видно → `$.vfx` (visual effects, это и есть `r2dvfx`).**

«Удар» перестаёт быть одной чёрной коробкой: он становится композицией —
`$.vfx.play('hit.spark')` (картинка, тряска, hit-stop) + `$.sfx.play('hit.metal')`
(звук), либо одной спекой `$.vfx`, где слой `use:'sfx.play'`.

### F1. Таблица переезда

| Сейчас | Куда | Почему |
|---|---|---|
| `$.fx.flash`, `flashLeft` | `$.vfx.flash` | визуальное |
| `$.fx.shockwave` | `$.vfx.shockwave` | визуальное |
| `$.fx.lightning` | `$.vfx.lightning` | визуальное |
| `$.fx.pulse` | `$.vfx.pulse` | визуальное |
| `$.fx.trail`, `ribbon`, `pushRibbon` | `$.vfx.trail/ribbon` | визуальное |
| `$.fx.attractor` | `$.vfx.attractor` | визуальное (влияет на частицы) |
| `$.fx.hitStop` | `$.vfx.hitStop` | тайминг кадра, но видимый эффект |
| `$.fx.clear`, `stats` | `$.vfx.clear/stats` | визуальная подсистема |
| `$.fx.impact` | `$.vfx.impact` (визуальные слои) + звук через `$.sfx` | разделение по правилу |
| `$.fx.installHits` / `$.hits` | `$.sfx.presets` (звук) + `$.vfx.impact` (картинка) | пресеты попадания — это и то, и другое; пресет остаётся один, но каждая часть зовётся из своего пространства |

### F2. Политика миграции (не ломать игры молча)

| Шаг | Как |
|---|---|
| вводим | `$.vfx.*` (r2dvfx) и `$.sfx.*` — целевые имена |
| старое | `$.fx.*` остаётся **работающим алиасом** на один минор; при вызове — **одно** дедуплицированное предупреждение «`$.fx.flash` устарело: используйте `$.vfx.flash`» |
| заморозка | новые имена добавляются в `api_freeze --write`; старые держатся до удаления |
| удаление | в следующем миноре, отдельным коммитом, с записью в CHANGELOG и таблицей миграции в `docs/highlevel/migration.md` |
| тест | mapping-тест: каждый старый вызов даёт **тот же результат**, что новый (числа/кадр), и предупреждение приходит **ровно один раз** |

**Приёмка:** (1) `$.vfx`/`$.sfx` живут и покрыты докой (`vfx.md`, `sfx.md`); (2) в `$.sfx`
