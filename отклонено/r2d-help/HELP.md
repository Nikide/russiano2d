# r2d-help — CLI-помощник по `$` API

`r2d-help` отвечает на вопрос «как это сделать в R2D» списком **настоящих**
имён API и разделов документации. Он нужен прежде всего ИИ-агенту: вместо
чтения всего справочника агент спрашивает помощника и получает структуру —
имя, сигнатуру, файл и строку объявления, страницу документации.

Это отдельный бинарник SDK, только CLI: один запуск — один JSON-объект на
stdout. Демона, сервера и сетевых запросов нет.

---

## 1. Использование

```sh
r2d-help как сделать чтобы враг шёл по пути       # то же, что search
r2d-help search "сохранить прогресс" --top 5
r2d-help "tween alpha" --text                      # для человека
r2d-help show navigateTo                           # объявление + разделы docs
r2d-help show '$.nav.mesh'
r2d-help index --root .                            # собрать/обновить индекс
r2d-help status
r2d-help embed "текст" --query --model f.gguf      # вектор текста (сверка модели)
```

| Флаг | Смысл |
|---|---|
| `--top N` | сколько результатов (по умолчанию 8, максимум 50) |
| `--text` | человекочитаемый вывод вместо JSON |
| `--index f` | файл индекса (по умолчанию `r2d-help.idx` рядом с бинарником, или `R2D_HELP_INDEX`) |
| `--model f.gguf` | модель эмбеддингов (по умолчанию `r2d-help.gguf` рядом с бинарником, или `R2D_HELP_MODEL`) |
| `--root dir` | корень репозитория движка (иначе ищется вверх от текущего каталога и от бинарника; или `R2D_HELP_ROOT`) |
| `--threads N` | потоки модели (поиск — 1, сборка индекса — все ядра) |
| `--no-update` | не пересобирать устаревший индекс |
| `--force` | `index`: пересобрать даже свежий индекс |

Коды выхода как у `r2d-sdk` ([SDK.md](SDK.md) §4): `0` — ok, `1` — выполнено,
но в данных есть ошибки, `2` — неверный вызов.

Ответ `search`:

```json
{ "ok": true, "query": "navigateTo", "mode": "hybrid",
  "index": { "entries": 2904, "api": 1161, "docs": 1743, "dim": 384, "updated": false, … },
  "results": [
    { "kind": "method", "name": ".navigateTo", "signature": ".navigateTo(target, opts)",
      "module": "nav", "location": "src/highlevel/nav.js:1738",
      "doc": "docs/highlevel/nav.md", "snippet": "…", "rank": 1,
      "score": 1.032787, "bm25": 18.52, "cosine": 0.81 } ],
  "diagnostics": [] }
```

`kind`: `method` — метод узла (`def`/`defGet`), `function` — функция
пространства имён (`$.nav.mesh`), `doc` — раздел документации. `mode`:
`hybrid` — BM25 и эмбеддинги, `bm25` — только лексический поиск (модели нет,
она другая или сборка без llama.cpp; причина — в `diagnostics`).

## 2. Что индексируется

Источник правды — код, а не ручной список:

* **методы узла** — каждый `def('имя', …)` / `defGet('имя', …)` в
  `src/highlevel/*.js`;
* **функции пространств имён** — члены объектного литерала, присвоенного
  `$.<имя>` (`const nav = { mesh(opts) {…} }; $.nav = nav;` → `$.nav.mesh`), и
  прямые `$.<имя> = (…) =>`;
* **описание** — комментарий `/** … */` или строки `//` прямо над объявлением,
  плюс до трёх строк из страницы модуля `docs/highlevel/<модуль>.md` и
  `docs/HIGH_LEVEL_API.md`, где вызывается это имя (заголовок вида
  `### .navigateTo(…)` берётся вместе с абзацем под ним);
* **документация** — каждый `docs/**/*.md`, разрезанный по заголовкам; длинный
  раздел режется на части по абзацам (не больше 1600 байт).

Разбор построчный и рассчитан на стиль кода движка
([highlevel/_CONTRACT.md](highlevel/_CONTRACT.md) §8, отступ 4 пробела). Что не
распознано как функция, всё равно находится через разделы документации.

## 3. Как ищет

1. **BM25** по тексту всех записей. Токенизатор понимает русский и английский:
   нижний регистр, `ё → е`, `camelCase` режется на части, длинные слова
   сводятся к основе из 6 букв, частые служебные слова отброшены.
2. **Эмбеддинги** — косинус между вектором запроса и векторами записей
   (int8, нормированы).
3. **Слияние рангов** (Reciprocal Rank Fusion, k = 60): запись, которая высоко
   в обоих списках, побеждает.
4. **Точное имя** в запросе (`navigateTo`, `$.nav.find`) поднимает эту запись
   наверх.

Оценки округляются, равные упорядочиваются по номеру записи, порядок файлов
отсортирован: одинаковый запрос даёт одинаковый ответ на любой платформе.

## 4. Модель

Любая GGUF-модель эмбеддингов предложений (с пулингом), которую читает
llama.cpp. Выбрана **multilingual-e5-small** (MIT, русский и английский,
384 измерения): префиксы `query: ` / `passage: ` помощник ставит сам, если в
имени модели есть `e5`.

Модель — данные, а не часть сборки. GGUF готовится один раз на машине
разработчика конвертером llama.cpp (`convert_hf_to_gguf.py`, тип `q8_0`) и
передаётся сборке:

```sh
cmake -S . -B build -DR2D_HELP_LLAMA=ON -DR2D_HELP_MODEL=/путь/multilingual-e5-small-q8_0.gguf
```

Сборка кладёт её рядом как `build/r2d-help.gguf` и считает векторы индекса.
Без модели всё работает в режиме `bm25`.

У e5-small в `config.json` архитектура `BertModel`, а словарь — sentencepiece
от XLM-RoBERTa; стандартный конвертер записал бы его как WordPiece и сломал
токенизацию. Поэтому конвертация идёт через `tools/help_train/convert_e5.py`,
а `tools/help_train/check_gguf.py` сверяет векторы GGUF (`r2d-help embed`) с
исходной моделью: косинус ниже 0,98 — конвертация сломана.

Весь путь — загрузка, конвертация, сверка, три замера (BM25, e5-small,
e5-small после дообучения на `tools/help_train/pairs.tsv`) — делает
`bash tools/help_train/run.sh` на машине с сетью к Hugging Face (Mac с Apple
Silicon обучает на MPS). Рабочее дерево не меняется: сборка идёт в отдельном
`git worktree`, отчёт — `build/help_train/report.txt`.

## 5. Автообновление

* **При сборке** цель `r2d-help-index` (входит в `ALL`) пересобирает
  `build/r2d-help.idx`, когда меняется любой `docs/**/*.md`,
  `src/highlevel/*.js`, модель или сам `r2d-help`. Новые файлы замечаются
  (`CONFIGURE_DEPENDS`).
* **При запуске** из репозитория помощник сверяет отпечаток источников
  (пути, размеры, mtime и версия правил сбора) с индексом и, если они
  разошлись, пересобирает индекс до ответа (`"updated": true`).
* **Векторы не считаются заново** для неизменённых записей: индекс хранит хэш
  текста каждой записи, вектор берётся из прошлого индекса той же модели.
  Правка одного раздела — пересчёт одного-двух векторов.

В поставленном пакете исходников `src/highlevel/` нет: там используется
индекс, собранный при выпуске (`tools/release.py` кладёт `r2d-help`,
`r2d-help.idx` и, если есть, `r2d-help.gguf` рядом с `r2d-sdk`).

## 6. Решения и ограничения

* **C11 + C API llama.cpp.** Помощник написан на C; C++ живёт только внутри
  статической библиотеки llama.cpp (запинена по коммиту в
  `sdk/help/CMakeLists.txt`). Движок и `r2d-sdk` не меняются и новых
  зависимостей не получают. Это решение владельца проекта (2026-10-09).
* **Только CPU, без OpenMP, без Metal/CUDA** — одинаковый результат и один
  бинарник без внешних библиотек.
* **llama.cpp выключен по умолчанию** (`R2D_HELP_LLAMA=OFF`): обычная сборка
  движка и автосборка пяти платформ не тянут тяжёлую C++-зависимость, пока
  модель не выбрана замером; помощник собирается с BM25. Включается
  `-DR2D_HELP_LLAMA=ON` (так делает `tools/help_train/run.sh`). llama.cpp
  берётся неглубоким клоном тега `b11517`.
* **Размер.** Linux x86_64 Release: 10,7 МБ, после `strip` 9,4 МБ. Из них
  код llama.cpp (все архитектуры моделей) ≈ 4,1 МБ, ggml ≈ 1,5 МБ, SDL3 из
  ядра SDK ≈ 1,4 МБ. Индекс без векторов — около 2,4 МБ; векторы e5-small
  добавят примерно 384 байта на запись (≈ 1,1 МБ на 2900 записей).
* **Качество.** Набор `tests/fixtures/help/queries.json` (50 вопросов на
  русском и английском, ожидаемые имена API) и замер
  `python3 tests/help_eval.py [--model f.gguf]`
  ([AGENT_IMPLEMENTATION_RULES.md](AGENT_IMPLEMENTATION_RULES.md), правило 6).

  | Режим | recall@1 | recall@5 | MRR | Условия |
  |---|---|---|---|---|
  | `bm25` | 0,18 | 0,36 | 0,26 | 2026-10-09, 2904 записи, Linux x86_64 |
  | `hybrid` (e5-small) | — | — | — | не измерено: модели не было в среде сборки |

  BM25 хорошо находит точные имена и ключевые слова, но не синонимы и
  словоформы («поставить на паузу» → `$.time.pause` мимо): это задача
  эмбеддингов. Снятие русских окончаний в токенизаторе проверено и
  отклонено: recall@5 0,40, но recall@1 0,12 и MRR 0,22 — первое место
  важнее для агента.
* Цепочка эмбеддингов проверена на крошечной BERT-модели со случайными весами
  (загрузка, пулинг, пересборка только изменённых записей, откат на BM25 при
  чужой модели и без модели); качество так не проверяется.
* Сокращение словаря модели (меньший GGUF) не реализовано.

## 7. Проверка

* `build/sdk/help/r2d_help_test <корень>` — токенизатор, файл индекса, BM25,
  слияние с векторами, детерминизм, сбор корпуса из этого репозитория;
  входит в `tools/ci_verify.py`.
* Ручная проверка с моделью: `r2d-help index --model f.gguf --force`, затем
  `r2d-help status` — `vectors` равно `entries`, `mode` в ответе `hybrid`.
* `python3 tests/help_eval.py [--model f.gguf]` — замер качества (§6).
